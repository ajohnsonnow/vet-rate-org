# bva_data_update.js — archived 2026-09-01

Generated by `scripts/scrapers/va_data_pipeline.py --generate-frontend`.
Archived because it was **generated but never consumed**.

## Why

- Zero importers. `git grep` for the file, `BVA_CONDITION_STATS`,
  `VA_PROCESSING_CURRENT` and `mergeLatestData` found no reference anywhere in
  `src/` — only the file's own docstring, the generator, and the scrapers
  README.
- Its payload was empty: `bvaDecisionsAnalyzed: 0`, `conditionsCovered: 0`.
  The generator emits a scaffold that only fills in once someone runs the BVA
  scraper, and nobody had.
- The preflight step that regenerated it had been crashing silently since
  2026-03-19 (`UnicodeEncodeError`, fixed in 554a62c2) — five months in which
  every release reported all checks green while this step did nothing. Nothing
  broke, because nothing read the output.

## What still works

The scraper and pipeline are untouched. `--generate-frontend` still writes to
`src/data/bva_data_update.js`; it will simply recreate the file if run.

    .venv/Scripts/python.exe scripts/scrapers/va_data_pipeline.py --generate-frontend

To bring it back: run the scraper so it has real content, `git mv` the file to
`src/data/`, and import it where the BVA statistics are actually rendered.
