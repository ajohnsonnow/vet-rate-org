# Egress Inventory — every network destination the app can reach

> RT1-6 deliverable for the red-team audit ([RED_TEAM_AUDIT_2026-06.md](./RED_TEAM_AUDIT_2026-06.md)).
> The CSP `connect-src` / `script-src` / `style-src` allowlists in [index.html](../index.html) are the
> **authoritative, browser-enforced** list of origins the app can talk to. This doc maps each one to
> _what data, which direction, what triggers it, and whether it's disclosed_ — so the privacy policy and
> README can be reconciled against reality (the "your data never leaves your device / zero data
> collection" claim must be literally true for every row, or qualified).
>
> **Last reconciled:** 2026-06-20. Re-run when the CSP changes.

Legend — **Direction:** ⬇️ inbound only (download/read, nothing user-authored leaves) · ⬆️ outbound (carries app/user data) · ↔️ both.

## Reconciliation actions (tracked in the sprint plan)

1. **RT1-5** — README must stop claiming "no analytics" (GoatCounter ships and is disclosed in the policy).
2. **RT1-3** — the published privacy policy must actually render (it ships `{t()}` placeholders) and should name every ⬆️/↔️ destination above.
3. **RT-5** — tighten `script-src` (drop `unsafe-eval`); **RT1-7** — self-host flag-icons, lazy-load Google API/GSI.
4. **CSP hygiene** — remove `api.anthropic.com` and `raw.githubusercontent.com` from `connect-src` if truly unused (keep the allowlist minimal so this inventory stays the source of truth).
5. **VA PHI** — when `VITE_VA_API_ENABLED` is turned on, add the VA OAuth/PHI flow to the threat model and a data-classification policy (audit gap-finding).
