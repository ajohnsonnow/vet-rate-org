## 0. How this audit was run (method + honesty)

This was an **adversarial red‑team pass whose explicit mandate was to find what the project's own "all 41 guides compliant / zero high‑severity findings" self‑assessment overlooked** — not to re‑confirm the scoreboard.

- **58‑agent workflow**, 12 dimensions, three stages: independent finder → adversarial verifier (default‑to‑refute) per substantive finding → a completeness/gap critic over all summaries. ~3M tokens, 822 tool calls.
- **63 dimension findings**: **33 confirmed**, 12 partial (legitimate but need scoping/counsel), 18 passed‑through (low/enhancement, not adversarially re‑checked).
- **Gap‑critic added 7 cross‑cutting findings** the per‑dimension finders missed (the most important ones — see §2).
- **Lead spot‑checks (verified by hand, not just agent‑reported):** the bundled Gemini key path, the English‑only crisis regex, the live `formsubmit.co` egress, the CSP value, the DOMPurify‑noop blast radius, the GoatCounter disclosure status.
- **Two deep follow‑ups** because the frontend/brand and performance finders returned degraded stubs on a rate‑limit retry — both re‑run at depth (§6, §7).

**Honesty notes / limits:**

- I **could not run a browser or Lighthouse.** All visual, contrast, motion, and Core‑Web‑Vitals claims are inferred from code/CSS/config and are marked as such. A live visual + NVDA + throttled‑mobile pass remains a manual must‑do.
- **Legal/compliance items are flagged, not adjudicated.** Where a concern is genuinely legal (UPL, FTC substantiation, CCPA/GDPR thresholds), the ticket says `needs-decision` and routes to counsel — do not treat my framing as legal advice.
- Some findings **overlap a parallel audit** already in‑flight (`audit/2026-06-cfile/`). Where that audit already fixed something (e.g. the BugSquasher `formsubmit.co` endpoint), this plan only covers the **unfixed siblings** and says so.
- The "App.jsx is a 3,653‑line monolith" premise is **stale** — it is now a 148‑line shell with a clean `src/features/` split. That work is genuinely done; this plan does not re‑litigate it.

## 1. Executive summary — your questions, answered directly

**Q: Did we overlook anything? Did we miss any aspect?**
Yes — and the miss has a single shape that recurs in almost every dimension:

> **The defenses exist, are well‑designed, and pass their isolated unit tests — but they are not wired into the real, high‑traffic code paths.** The scoreboard reads "compliant" because the _primitive_ exists; the red team checked whether the _gate actually fires in production_, and repeatedly it does not.

Concrete instances of that one pattern:

- The output URL‑exfiltration filter (`stripUntrustedUrls`) is **never called in production** — only inside its own tests (PI‑01).
- Spotlight delimiters / dual‑LLM / the PII‑scrubber‑as‑firewall protect **one low‑traffic legal‑RAG path**, while raw OCR text from C‑files/DD214s flows into the model un‑spotlighted (PI‑02, PI‑03).
- The strong forbidden‑phrase + CFR‑grounding AI validator is **dead code** due to a `taskType`‑as‑context bug (AIS‑01).
- The crisis interceptor is **English‑regex‑only** even though a multilingual detector already exists — it's just wired only to voice output (AIS‑04).
- The a11y "WCAG compliant" signal comes from a jsdom suite that tests **synthetic markup with contrast checks disabled** (A11Y‑01); `pa11y` never runs (A11Y‑02).
- Custom Semgrep rules are **never loaded by any pipeline** (CICD‑01); several PR gates are **inert** and always green (CICD‑08).
- The green/gold design‑token pipeline is **real but used 0× in components** (D3).

**Q: Is the "your data NEVER leaves your device / zero data collection" promise true?**
**Not as written.** The data _layer_ is genuinely strong (local‑first, no analytics of user content, a real PII scrubber on egress). But the _communications_ layer contradicts the marketing:

- `FeatureRequest.jsx` and `CommunityRoadmap.jsx` **POST user free‑text + optional email to a third‑party broker** (`formsubmit.co`, owner's personal email hardcoded in the client bundle) — undisclosed (gap‑critic + verified).
- **GoatCounter analytics ships** (it _is_ disclosed in the privacy policy, but the README claims "no analytics").
- The published privacy policy itself is **non‑functional** — it ships unrendered `{t("…")}` React placeholders instead of prose (PRIV‑01/LEGAL‑01, verified).
- The BYOK Gemini path can **bake the owner's API key into the public build** (CICD‑10, verified).
  This is the highest‑stakes theme because trust is the entire value proposition to this population. See Sprint **RT‑1**.

**Q: Did we make all the tools correctly? Are there instructions?**
Mostly yes, with real defects. The dispatch architecture is sound (event‑driven feature clusters), but the **CMD+K command palette is a dead no‑op** (prop‑name mismatch — every selection silently does nothing, TOOL‑01); diagnostic‑code search **keys off array index** (TOOL‑02); there is **no agreed tool count** (prose 39 / registry 42 / tests 48, TOOL‑04); and the in‑app Field Manual gives the **entire Appeals cluster zero coverage** (TOOL‑03). Instructions exist (UserManual, BootCampTour) but are incomplete and have a literal unsubstituted placeholder in a headline (TOOL‑06). See Sprint **RT‑10**.

**Q: Did we cover all inputs/outputs/processes/laws/standards/best practices?**
Strong coverage with specific gaps: **encrypted/password‑protected PDFs are wholly unhandled** even though the VA ships C‑files that way (PARSE‑001); a "SECURE" encrypted‑zip helper actually **ships plaintext** (PARSE‑002); the combined‑rating engine has **two divergent implementations** and one **over‑applies the bilateral factor** (PARSE‑004 — a correctness bug in the core calculator). On laws/standards: missing CCPA/CPRA/GDPR data‑subject‑rights disclosures (LEGAL‑02), no point‑of‑generation **18 U.S.C. 1001** false‑statement warning on AI‑drafted evidence (LEGAL‑03), and an unaddressed **UPL / 38 C.F.R. 14.629** boundary on the AI‑argument tools (LEGAL‑06). See Sprints **RT‑2, RT‑7, RT‑9**.

**Q: Do we have a beautiful front end, or is it just standard? What is our brand style?**
**Honest verdict: competent, trending standard — not beautiful, and not yet on‑brand.** The brand is _a strong concept on an incoherent implementation_:

- **Brand style (as built):** a verbal **military/tactical** identity ("Command Center", "Muster Call", "Loading Bunker", real drill terminology) that is genuinely veteran‑aware — plus a "Luna" cat mascot that's barely present (6 files) and tonally at odds with the tactical voice. The _intended_ palette is olive‑green/gold; the _actual_ on‑screen palette is a **rainbow** (each tool category got its own unrelated blue/teal/violet/rose/amber family), and the flagship hero is **blue→indigo→purple** — off‑brand.
- **Why it's "standard":** there is **no component‑primitive layer** (no `Button`/`Card`/`Badge`/`Input`), which forces ~1028 inline color classes and inconsistent radii/shadows/states; `index.css` is 2521 lines of mostly `!important` per‑ramp overrides; the token pipeline is dead code; `va-gold` renders as **two different colors** depending on whether you use the Tailwind class or the CSS utility.
- **The good:** the accessibility system (TBI "Night Bunker" theme, AAA mode, colorblind palettes, reduced‑motion, 44px targets, pinned crisis line) is **above average and fit‑for‑audience** — that's the best thing here and must not regress.
  Full assessment + a 15‑item enrichment roadmap in §6 / Sprint **RT‑14**.

**Overall posture verdict:** This is a **conscientious, security‑aware, accessibility‑aware codebase whose biggest risk is the gap between its documented intentions and its wired reality** — plus a trust‑integrity problem where marketing claims outrun the code. None of the confirmed findings is a remote‑code‑exec class hole; the danger profile is _quiet failure of a safety/privacy control the project believes is active_, which for a suicide‑risk, PHI‑handling, federal‑claim‑filing population is exactly the profile that matters.

## 2. The seven cross‑cutting themes (drive the sprint order)

1. **Egress reality vs. the "never leaves your device" promise.** Build one authoritative egress inventory (Gemini BYOK, Anthropic, formsubmit.co, GoatCounter, jsDelivr/HF CDNs, api.va.gov), reconcile it against the CSP `connect-src` allowlist, and make the README + privacy policy literally true for every channel. → **RT‑1**
2. **Defenses exist but aren't wired into the real call paths.** A "does this gate actually fire in prod?" integration pass across injection, AI‑safety, a11y, and CI. → **RT‑2, RT‑3, RT‑4, RT‑11, RT‑13**
3. **The XSS backstop is largely inert.** `unsafe-inline`+`unsafe-eval` in CSP, DOMPurify aliased to a no‑op, and 6 `dangerouslySetInnerHTML` sites whose "safe‑by‑construction" comments falsely cite the CSP. → **RT‑5**
4. **Non‑English veterans are the systematically under‑protected persona** — crisis detection, PII scrubbing, _and_ i18n integrity of safety‑critical disclosures all degrade for the same multilingual, suicide‑risk, federal‑claim‑filing user. → **RT‑3**
5. **Sensitive‑data classification & at‑rest protection.** Unify plaintext localStorage/IndexedDB PII, VA‑OAuth‑fetched government PHI, and the email‑as‑passphrase cloud‑sync into one data‑classification + encryption‑at‑rest workstream; gate the highest class from any external egress. → **RT‑6**
6. **Medico‑legal artifact integrity** — the file the veteran actually _files_. Point‑of‑output human verification AND an in‑document 18 U.S.C. 1001 / "AI‑drafted, verify every fact" warning embedded in the exported PDF/DOCX, distinct from on‑screen warnings. → **RT‑2**
7. **Marketing‑claim honesty as a trust workstream.** Every checkable claim (React 19 vs 18.2, tool count, "$2.09M value", "zero data collection", "free forever") must match the code, because demonstrable false claims on easy items corrode trust in the privacy claims that carry legal and human stakes. → **RT‑1, RT‑9**

## 3. Strengths — do not regress these

The audit found genuinely strong work; remediation must preserve it:

- **Cloud‑backup crypto core** is excellent: AES‑256‑GCM with AAD domain separation, PBKDF2‑SHA256 @ 600k iterations, per‑encryption random salt+IV (no reuse), an S16 device keystore with RFC‑3394 AES‑KW wrapping and crash‑safe verify‑before‑commit rotation. PKCE is textbook.
- **Accessibility foundation** is above average: real focus‑trap hook with restoration, centralized `ResponsiveModal` with correct ARIA, OS + in‑app reduced‑motion, 44px targets, six high‑contrast/colorblind palettes, a TBI "Night Bunker" theme, keyboard‑operable BodyMapSelector with `aria-live`.
- **Build/code‑splitting**: every heavy dep (web‑llm, wllama, transformers, tesseract, pdfjs) is lazy/dynamic — the entry bundle is _not_ bloated.
- **Architecture**: `App.jsx` is a 148‑line shell with a clean 44‑directory `src/features/` split and per‑feature error boundaries.
- **Injection toolkit design**: spotlight helpers, a clean dual‑LLM extractor/synthesizer, an output URL allowlist, a unicode‑normalizing PII scrubber, an agent capability boundary, a 44‑case red‑team suite. (The design is good — the wiring is the gap.)
- **Disclosure baseline**: a real Non‑Accreditation Clause, Medical Disclaimer, AI‑limitations warning, a persistent "not affiliated with the VA" footer, and the SharkRadar predatory‑service scanner — a genuine consumer‑protection feature.
- **Large‑file ingestion**: 300MB+ C‑file streaming through IndexedDB keeps RAM flat; a multi‑strategy JSON‑repair ladder; an explicit "partial analysis" banner so partial is never mistaken for complete.

### Sprint RT‑15 — Calm, Restrained Restyle (de‑saturate; trust‑first) `P1` · **owner‑requested, run before RT‑14**

**Why (owner directive, 2026‑06‑20):** The core audience is older veterans, frequently in **chronic pain** and managing **TBI/PTSD** (stimulation‑ and contrast‑sensitive), and skewing **traditional/serious** in taste. The current multi‑color, emoji‑heavy, mascot‑forward UI (verified live in §6.1: blue/teal/yellow/pink/**purple**/indigo pills, orange/purple tool chrome) reads as a youthful consumer app — which can feel **unserious, busy, and alienating** to that user, and the color/contrast churn is **physically fatiguing** for pain/TBI. The site should feel like a **calm, disciplined, trustworthy command post**: few colors, high legibility, restraint over decoration. This sprint sets the palette direction; RT‑14's primitives/states/modals then build on it.

**North star — "3 colors + neutrals," color carries meaning, never decoration:**

- **Primary:** deep military/olive green (the existing `va-blue` token value `#2d5016` — keep, it's the one genuinely on‑brand color). Used for primary surfaces, headers, primary CTAs.
- **Neutrals:** a warm charcoal/**stone** scale (text, borders, cards, tool surfaces) — this _replaces_ the per‑category blue/teal/violet/rose/amber families.

## 6. Brand & frontend — full assessment

_(Code‑only review; no browser run. Citations are file:line.)_

**Brand characterization.** A **coherent concept on an incoherent implementation.** The verbal identity is strong and intentional — a consistent military/tactical metaphor ("Command Center" `HomeMain.jsx:48`, "Muster Call", "Loading Bunker", "Tactical Calculator", real drill terminology `MusterCall.jsx:13‑22`) plus a genuinely veteran‑aware accessibility posture (TBI "Night Bunker" theme `index.css:240‑258`, AAA mode, four colorblind palettes, in‑app reduced‑motion, a crisis line pinned to the header `Header.jsx:204‑215`). That is the best thing in the front end.

The **visual** identity does not match the concept:

- **The green/gold token system is theoretical.** A real Style‑Dictionary pipeline exists (`design-tokens.js` → `tailwind.config.js:14`), but its branded palettes (`medal-green`, `service-blue`, `tactical-grey`, `warning-gold`) have **0 component usages**; components use ~1028 raw Tailwind ramp classes across 60+ files.
- **The on‑screen palette is a rainbow.** Each tool category got its own unrelated family (blue/indigo for Calculate, teal/emerald for Discover, violet for Evidence, rose for Quality, amber for Maximize). The flagship hero is **blue→indigo→purple** (`HomeFeatureCards.jsx:28,62`) — the single most prominent element is off‑brand; that gradient recurs ~50× across 30+ files.
- **`va-blue`/`va-gold` render two different colors.** Tokens say green/olive (`#2d5016`/`#88b04b`); the CSS utilities hardcode the _old_ federal palette (`.text-va-gold{#fdb913}`, `.bg-va-blue{#003f87}` `index.css:1763‑1777`); `<meta theme-color>`=`#003f87`. Same token, two brands.
- **Mascot barely present.** "Luna" has bespoke entrance animations (`tailwind.config.js:66‑142`) but appears in only 6 files, mostly marketing — and a pouncing‑cat motion language is tonally at odds with the tactical voice.

**Verdict: competent, trending standard — not beautiful.** Drivers: **no component‑primitive layer** (no `Button`/`Card`/`Badge`/`Input` — the root cause of the 1028 inline colors and inconsistent radii/shadows); `index.css` is 2521 lines of mostly `!important` per‑ramp overrides (what you write _instead of_ tokens); two different loading spinners; three icon systems (emoji + inline SVG + lucide); thin empty/error states. What keeps it above "standard": the accessibility system, the clean `ResponsiveModal`, reduced‑motion handling, and the warm light‑mode palette.

The **defects table (D1‑D13)** and the **enrichment roadmap (E1‑E15)** are executed as Sprint **RT‑14** above. Highest‑leverage move: **build the primitive layer** — it converts every other fix from per‑file to systemic.

## 7. Performance — findings

_(Code/config‑only; no Lighthouse run. Maturity: standard, trending strong on code‑splitting; weak on enforcement.)_ Good news first: every heavy dep is lazy/dynamic — the **entry bundle is not bloated** — and device‑capability gating is well‑designed and correctly applied on the WebLLM path. The weaknesses are enforcement + the wllama/big‑file paths, executed as Sprint **RT‑8**:

- **P1 (high)** prod COOP/COEP absent (`render.yaml`) → no cross‑origin isolation → WASM single‑thread → 2‑8× slower OCR/LLM on weak devices.
- **P2 (high)** bundle‑budget gate not in CI; `.size-limit.json` misconfigured so the PR action no‑ops.
- **P3 (high)** wllama 7B path ungated in the `unifiedAIService` wrapper → a phone can trigger a ~4GB download then OOM.
- **P4 (high)** 300MB+ PDF read fully into one ArrayBuffer before processing → OOM on 2‑4GB phones.
- **P5 (med)** main‑thread rasterization/preprocessing freezes the UI per page.
- **P6 (med)** no `storage.estimate()` guard before multi‑GB model writes.
- **P7 (med)** eager Google API/GSI scripts on every page.
- **P8 (low)** mobile LCP/TBT only `warn` in Lighthouse CI.
